# 安全执行边界

[← 返回总览](./README.md)

本文定义 sdgb-worker 作为黑盒服务必须满足的行为，不描述机台侧协议、服务地址、认证材料、请求结构或源码实现。

## 1. 黑盒职责

对于每个 get_music_score 任务，sdgb-worker 必须：

1. 只处理 backend 分配的任务。
2. 校验二维码有效性和账号归属。
3. 在确认二维码对应账号与 backend 预期绑定一致后，才进入受保护的成绩读取阶段。
4. 生成一次完整且有边界的成绩快照。
5. 无论读取成功或失败，都尝试安全结束本次临时登录状态。
6. 只有在清理已经确认成功后，才允许 backend 持久化成绩。
7. 对 backend 上报稳定阶段、进度、清理状态和脱敏错误。

任何机台侧交互均为 worker 私有实现，不属于共享 contract。

## 2. 行为生命周期

用户可见生命周期为：

    queued
      -> qr_auth
      -> preview
      -> login
      -> get_music
      -> logout
      -> persist
      -> completed

失败路径可以从任一处理中阶段进入 cleanup，随后进入 failed。若清理暂时无法确认，任务保持可查询并阻止同一用户再次提交二维码任务。

上述阶段只表达用户可理解的进度。它们不能用于推断或固定 worker 内部的请求数量、调用顺序或实现组件。

## 3. 一次性与隔离

- 每次二维码更新都要求用户提交当前有效的新二维码。
- 二维码不得用于下一次更新或自动更新。
- 并发任务之间的临时状态必须隔离，不能串用账号或成绩。
- 任务中断后不得继续复用旧二维码完成业务读取。
- 恢复流程只用于安全收尾，不用于恢复或继续成绩读取。

## 4. 完整性要求

- 结果必须能表示 achievement、DX Score、FC/AP 和 FS/FDX。
- worker 必须拒绝明显不完整、越界或无法验证的成绩快照。
- backend 收到结果后仍需执行独立 schema 和业务校验。
- 没有可用成绩时不得用空结果覆盖用户现有 sync。

本文不固定机台侧分页、批量大小、字段编号或返回结构。

## 5. 超时、重试与限流

- 任务必须有总超时，不能无限占用执行槽位。
- 外部交互必须使用有界重试。
- 可能改变临时登录状态的操作不得盲目重放。
- 整体吞吐必须受并发和速率限制保护。
- 超时首先进入安全收尾，再报告业务失败。

具体数值和调度算法属于部署配置及 worker 私有实现，不写入本公开 spec。

## 6. 数据生命周期

| 数据 | 生命周期要求 |
| --- | --- |
| 二维码 | 任务执行所需的最短时间；终态后清除 |
| 临时会话凭据 | 仅在 worker 私有边界和安全收尾所需的短期记录中存在 |
| 原始成绩快照 | 仅用于本次 backend finalization；不作为长期任务结果 |
| 结果摘要 | 可长期保存 syncId、scoreCount 和终态 |

worker 向 backend 报告的错误必须先脱敏。机台侧原始错误、地址、请求和响应不得进入任务视图或普通日志。

## 7. 文档保密边界

- 机台侧协议及服务定位方式；
- 请求与响应样例、字段生成方法和调用参数；
- 认证、签名、加密与会话传输细节；
- 运行时秘密的内容或派生方式；
- sdgb-worker 私有目录、文件、类、函数和依赖选择；
- 精确重试、限流和恢复算法。

如需变更这些内容，应在受控的私有运维资料中维护，并确保不影响本文定义的公开行为。
